# Bypass Only — снять отказ, не наводя его

## Коротко

**Статус: завершён (15.10.2026). Исход вырожденный** — разбор в [reports/results.md](reports/results.md).
При $\lambda_{inv} = 1$ векторы `invariant` каузально инертны: не наводят отказ ни в одну сторону, но
и не снимают его (ASR 0.34 — как у случайного направления), общей компоненты нет. Отличить
«свойство модели» от «слишком большого веса» можно только свипом $\lambda_{inv}$.

Ищем одномерное направление, **аблация** которого снимает отказ, а **добавление** в любую
сторону ничего не меняет. Лосс RDO, в котором слагаемое наведения обращено: вместо «добавление
$+\alpha\hat r$ вызывает отказ» — «добавление $\pm\alpha\hat r$ не меняет выход на harmless» (KL к
чистой модели). Аблация и retain — как в статье.

Зачем: в loss_terms общая ось RDO оказалась осью аблации, а без слагаемого наведения
векторы `no_add` всё равно частично наводят отказ, и знак у них случайный. Если направление
«только снятие» существует и лежит на той же оси, снятие и наведение разделимы (read/write из
common_axis); если запрет наведения ломает снятие, это одна ось, работающая в обе стороны.
Постановка, лосс, исходы и границы — в [idea.md](idea.md).

## Порядок прогонов

```
1_train.sh     GPU  12 обучений invariant (≥ 34 ГБ на карте)
2_geometry.sh  CPU  компоненты base / no_add / no_abl / invariant → reports/geometry.md
3_causal.sh    GPU  аблация + наведение в обе стороны, 112 направлений → reports/causal.md
4_sweep.sh     GPU  свип λ_inv ∈ {0.3, 0.1, 0.03}: 36 обучений (два процесса на карте), затем 2 и 3
queue.sh            всё это по очереди: ждёт закрытия очередей loss_terms, проверяет, что
                    no_add/no_abl готовы и форк на нужной ветке, дальше — по одной задаче на любой
                    карте с местом, пауза минуту между задачами, проверка результатов, повтор до 3 раз
```

Перед запуском на сервере форк должен быть на ветке `feat/rdo-invariant-addition` (режим
`rdo.py --addition_mode invariant`; содержит и всё из `feat/rdo-free-norm`).

```bash
tmux new-session -d -s fz-bypass-only \
  "bash experiments/bypass_only/run/queue.sh 2>&1 | tee -a ~/f.zakharov/bypass_only_queue.log"
```

Код шагов общий с loss_terms: правки там (например, в `causal.py`) действуют и здесь.
