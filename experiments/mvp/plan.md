# Concept Dims MVP — план этапов

Пошаговый план выполнения пилота. Идея — [idea.md](idea.md), технические детали —
[technical-spec.md](technical-spec.md).

**Условные обозначения:** 🖥️ GPU — запускает **пользователь** (правило проекта);
💻 CPU — может делать Claude (в т.ч. локально); 📝 — правка кода/данных.

## Ключевые вводные из разбора репозитория
- **Тренер конусов = `rdo.py --train_cone`** (не пайплайн). Блок `__main__`
  (rdo.py:1086-1099) сам перебирает `range(min_cone_dim, max_cone_dim+1)`, тёпло
  стартуя каждую d от оптимума предыдущей.
- **Ввод своих промптов — без правок кода:** положить
  `data/<name>_splits/harmful_train.json` + `harmless_train.json` в формате
  `[{"instruction": "...", "source": "..."}]` и запустить `--splits <name>`
  (rdo.py:200-201; читается только `instruction`). Категорийного фильтра в рантайме нет —
  фильтруем на своём этапе сэмплинга.
- **⚠️ Метрики пишутся только в wandb** (`train/basis_bypass_score`,
  `train/basis_retain_loss`, rdo.py:854-900). У нас wandb под запретом (политика) → нужна
  правка: отключить wandb и **сохранять per-d bypass/retain на диск** (иначе нечем считать elbow).
- **Активации входа:** переиспользовать паттерн `get_mean_activations`
  (generate_directions.py:18) — заменить усреднение на **сохранение** пер-промптного
  вектора последнего токена на слое L (hook на `model_base.model_block_modules[L]`).

## Этап 0 — Пререквизиты 📝🖥️
- Доступ к `google/gemma-2-2b-it` (gated на HF) + токен; `.env` в форке:
  `HUGGINGFACE_CACHE_DIR`, `SAVE_DIR`, `DIM_DIR` (шаблон `.env_example`).
- **wandb выключить** (`WANDB_MODE=disabled` / offline-стаб) — политика.
- **DIM-направление — своё на каждую ступень.** rdo.py его НЕ генерирует: при отсутствии
  файлов кидает `FileNotFoundError` (rdo.py:180-183). Поэтому **заранее** посчитать DIM
  для каждой ступени пайплайном direction-generation (`generate_directions` → `direction.pt`
  + `direction_metadata.json` + `mean_diffs.pt`) **на данных этой же ступени**. 🖥️
  Путь DIM привязан к `model_id` (rdo.py:174), не к splits, поэтому разводим ступени по
  разным `DIM_DIR` (напр. `dim/theft`, `dim/illegal`, `dim/malicious`) и подставляем нужный
  per-run. Следствие: у каждой ступени свои `best_layer`/`alpha`/targets — «родные» условия.
- Зафиксировать параметры: слой **L** (серединный), **N=900**, **сид = 21** (один,
  из-за ограничения ресурсов), retain-порог `kl_threshold`, порог elbow, верхняя граница `D` (напр. 10).
  Открытый нюанс: мерить `1 − cos` на фиксированном L (сравнимость входной оси) или на
  собственном `best_layer` каждой ступени — решить при фиксации L.

## Этап 1 — Данные и сэмплинг 💻📝
- Загрузить SALAD `base_set`; собрать 3 вложенные ступени:
  Theft (лист) / Illegal Activities (задача) / Malicious Use (домен).
- Сабсэмпл **N=900** на ступень, **сид = 21** (один прогон).
- Подготовить общий harmless-набор (alpaca-стиль, ≥900) — нужен для addition/retain лоссов
  (harmless усекается до длины harmful, rdo.py:203).
- Эмитить на каждую ступень `data/<rung>_splits/harmful_train.json`
  (+ общий `harmless_train.json`) в нужном формате.
- **Сохранить точные наборы промптов** — один источник и для входной, и для выходной оси.

## Этап 2 — Ось входа: разброс концепта (1 − cos)
- **2a 🖥️📝** новый мини-скрипт: forward по N промптам ступени, снять активацию
  **последнего токена на слое L** через store-hook (переиспользуя `add_hooks`
  hook_utils.py:10 + `ModelBase` из `construct_model_base`), дамп матрицы `[N, d]` на диск.
- **2b 💻** посчитать среднее попарное `1 − cos` из дампа (по ступени) — одно число на ступень.
- **Санити-чек:** упорядоченность разброса домен > задача > лист.

## Этап 3 — Ось выхода: перебор размерности конуса
- **3a 📝** минимальные правки rdo.py-пути: (i) wandb в disabled; (ii) **дамп на диск
  per-d** `bypass` и `retain` (+ `lowest_loss_vector.pt` по каждой d) — чтобы Этап 4 был CPU.
- **3b 🖥️** на каждую ступень (с её `DIM_DIR` из Этапа 0):
  `DIM_DIR=dim/<rung> rdo.py --train_cone --min_cone_dim 1 --max_cone_dim D
  --splits <rung> --model google/gemma-2-2b-it` (сначала генерит targets — GPU, затем
  обучает конусы d=1…D). Каждая ступень использует свой DIM.
- **Компьют:** 3 ступени × D обучений конуса (один сид) — основной GPU-расход пилота.

## Этап 4 — Определение d\* (elbow) 💻
- Из сохранённых per-d `bypass`/`retain` (Этап 3a) построить кривую `bypass(d)` при
  фиксированном retain-бюджете.
- **d\*** = elbow: где прирост bypass при +1 измерении падает ниже порога.
- Один сид (seed=21) → одно значение d\* на ступень (без агрегации).

## Этап 5 — Синтез и результат 💻
- Свести `(1 − cos, d\*)` по трём ступеням; график `x = 1−cos`, `y = d\*`.
- Применить правило чтения (рост → H1, плато → против H1); заполнить таблицу результата
  в [idea.md](idea.md) / [technical-spec.md](technical-spec.md).

## Этап 6 — Выводы 💻
- Краткий итог + честные границы (нет контроля → только связь; 3 точки; тавтология-риск).
- Наметить следующий шаг (контрольная лестница, больше ступеней).

## Разделение труда (правила проекта)
- 🖥️ **Пользователь (GPU):** генерация DIM-направления (0), снятие активаций (2a),
  генерация targets + обучение конусов (3b). Claude готовит команды.
- 💻 **Claude (CPU):** сэмплинг и эмит сплитов (1), подсчёт `1 − cos` (2b), правки кода
  (3a), elbow (4), синтез и графики (5-6).

## Открытые вопросы к фиксации перед стартом
- Точный слой L и его согласование с тем, где живёт направление.
- `kl_threshold` (retain-бюджет) и порог elbow.
- Нужен ли рефактор `RefusalCone` (глобальный `model`, `.cuda()`) — для MVP через
  `rdo.py --train_cone` **не обязателен** (сгодится встроенный sweep); рефактор — если
  захотим звать конус из своего кода.
