## 2. Сэмплирование

Все три ступени сабсэмплятся до общего **N = 900** (порядка размера листа), одним
фиксированным сидом **seed = 21** (из-за ограничения ресурсов — один прогон, без
агрегации по сидам). Причина уравнивания N: и `1 − cos`, и извлечение конуса зависят от числа
примеров — без уравнивания «уровень лестницы» спутается с «размером выборки», и рост
размерности нельзя будет отличить от артефакта N.

## 3. Ось входа — разброс концепта: `1 − cos`

- **Мера:** среднее попарное `1 − cos(a_i, a_j)` по активациям промптов ступени
  (одно число; больше — разнороднее корпус).
- **Пространство:** активации модели — residual stream, **последний токен**,
  **серединный слой** L.
- Тот же слой L используется и для извлечения конуса (оси согласованы).

## 4. Ось выхода — размерность отказа: concept cones + перебор d

- **Метод** — concept cones из RDO (Wollschläger et al.), как в исходной статье:
  обучаем конус растущей размерности `d = 1, 2, … 10`.
- **Перебор d уже встроен** в `rdo.py`: блок `__main__` гоняет
  `range(min_cone_dim, max_cone_dim+1)` и на каждой d вызывает `train_refusal_cone`
  (`rdo.py:1087-1095`) — достаточно флагов `--min_cone_dim 1 --max_cone_dim 10`.
- На каждой d репозиторий уже считает **bypass/ASR** (`basis_bypass_scores`, `rdo.py:854`)
  и **retain через KL** (`kl_div_fn`, retain-лосс).
- **Оптимальная d\*** — по **плато ASR (elbow):** d\*, где прирост bypass-ASR при +1
  измерении падает ниже порога при фиксированном retain-бюджете (retain в пайплайне
  задаётся `kl_threshold` в `select_cone_basis`, `select_direction.py:509`).
  ⚠️ Сам выбор d\* по elbow **не встроен** — считаем его поверх кривой bypass(d).
  d\* и есть измеренная размерность refusal-подпространства ступени.
- **Компьют:** `d = 1…10` × 3 ступени (один сид, seed=21) — обучений конуса. Elbow обычно
  на малых d, поэтому верхнюю границу 10 можно ужать, увидев, где плато.

## 6. Что переиспользуем из RDO-репозитория

- `RefusalCone` и `refusal_cone_optimization` (`rdo.py`) — обучение конуса заданной размерности.
- `get_bypass_scores` (`scoring.py`) — ASR/bypass для критерия плато.
- ⚠️ `RefusalCone` завязан на глобальный `model` и хардкод `.cuda()` — потребуется
  аккуратный рефактор для чистого перебора размерности
  (см. [../../notes/concept-cones.md](../../notes/concept-cones.md)).
- Карта кода библиотеки — [../../notes/geometry-of-refusal-map.md](../../notes/geometry-of-refusal-map.md).

## 7. Модель и параметры

- **Модель:** по умолчанию `google/gemma-2-2b-it` (gated на HF — нужен доступ/токен).
- Слой L (серединный) и позиция токена (последний) — единые для входа и выхода.
- retain-бюджет (`kl_threshold`) и порог «плато» для elbow.
- Сид фиксирован: **seed = 21** (один прогон, без агрегации по сидам).

## 8. Открытые технические вопросы

- Точное значение L (какой именно серединный слой) и его фиксация.
- Конкретные `kl_threshold` и порог elbow.
- Реализация подсчёта elbow поверх логов bypass(d).
- Когда подключать контрольную лестницу (переход за рамки MVP).
