# Loss Terms — какое слагаемое RDO создаёт общую компоненту

## Коротко

**Статус: подготовлен, не запущен.**

Две гипотезы на одной сетке вариантов лосса одномерного RDO:

- **H1:** общую компоненту RDO-векторов создаёт концепт-независимое слагаемое наведения
  отказа $L_{add}$, а не концептная аблация $L_{abl}$. Проверка — варианты без $L_{add}$
  (`no_add`) и без $L_{abl}$ (`no_abl`);
- **H2:** если вектор в $L_{add}$ не нормировать и штрафовать его норму (`free_norm`),
  ненужные компоненты затухнут, и сиды сойдутся к одной оси без пересечения.

Данные, DIM, кэш целей и гиперпараметры — из базового запуска
`qwen2.5-3b_salad-o1o2o5o6` (shared-refusal-component), сиды — первые три каждого домена
оттуда же. Поэтому каждый новый вектор имеет пару в `base` с тем же стартом.

## Порядок прогонов

```
0_calibrate_norm.sh  GPU  3 обучения: μ ∈ {0.03, 0.1, 0.3} на O1, сид 1 → reports/calibration.md
                          → вписать выбранное μ в NORM_LAMBDA (scripts/common.py), закоммитить
1_train.sh           GPU  36 обучений: no_add, no_abl, free_norm × 4 домена × 3 сида
2_geometry.sh        CPU  компоненты и согласованность → reports/geometry.md, components.pt
3_causal.sh          GPU  аблация и наведение для 60 направлений → reports/causal.md
```

Запуск по очередям (14.10): `run/queue.sh` — калибровка, `no_add`, `no_abl`;
`run/queue_finish.sh` — после неё калибровка μ = 1, `free_norm` (μ — автоматически по правилу
из `calibration.json`), геометрия, каузальные замеры. Обе — по одной задаче на любой карте с
достаточной памятью, с паузой минуту между задачами и проверкой результатов.

Всё идёт на **одной карте**. `no_add` и `no_abl` можно обучать, не дожидаясь калибровки:
им μ не нужно (`VARIANTS="no_add no_abl"`). При свободной памяти на той же карте можно
держать два процесса с разными `DOMAINS` — они пишут в разные каталоги.

Требует правки форка `geometry-of-refusal/rdo.py` (режим `--free_norm`, исправление
передачи гиперпараметров) — см. [idea.md](idea.md#правка-форка).
