# Common Axis — общая компонента отказа

## Коротко

Конусы отказа, обученные RDO на четырёх вложенных концептах SALAD с тремя сидами, делят
**одно общее направление**: его несут все 12 прогонов (доля в конусе 0.71–0.86 при случайном
уровне 0.05), и общей инициализацией это не объясняется. Направление не совпадает с DIM —
span всех четырёх DIM покрывает лишь 37% его энергии, — но работает лучше DIM: при равной
цене по retain оно снимает отказ на 0.98–1.00 против 0.90–0.95 и наводит отказ на безобидных
промптах (5.5% → 98.4%). Одной компоненты хватает там, где не хватает всего обученного конуса
из 12 рёбер.

Главный результат — разложение DIM. Вся его каузальная сила сидит в 18–30% энергии, которые
совпадают с этой компонентой: вычитаем её — и DIM перестаёт и наводить отказ (0.164 при
базовых 0.055), и снимать его (0.250 при базовых 0.258), хотя остаток сохраняет cos 0.84–0.90
с исходным вектором. Обратное не работает: компонента без DIM-части сохраняет почти всю силу.
Оставшиеся 70–82% DIM — **read**-компонента: она детектирует вредность промпта не хуже целого
DIM (AUROC 0.997) и причинно не участвует ни в чём. По глубине это видно как двойная
диссоциация: read-часть декодируется с нулевого слоя, write-часть до слоя 21 неотличима от
случайного направления и выходит на уровень ровно к слою 22 — тому самому, где работают
аблация и наведение.

Скрипты — в [scripts/](scripts/), раннеры — в [run/](run/), по одному на шаг; каждый раннер
в шапке говорит, нужен ли GPU и что читает. Артефакты (сами векторы, JSON с числами) лежат на
сервере в `<fork>/results/common_axis/` и в git не хранятся.

## Порядок прогонов

```
1_common_axis.sh    CPU   компонента внутри ступени (по сидам)
2_global_axis.sh    CPU   компонента по всем прогонам + контроль общего старта
3_mixed_axis.sh     CPU   конусы и DIM в одной популяции
4_ablate_axes.sh    GPU   аблация при выравненном KL
5_dim_residual.sh   GPU   остаток DIM после вычитания компоненты
6_induce_axes.sh    GPU   наведение отказа + кросс-нейтрализация
7_read_probe.sh     GPU   read-пробник по слоям
8_axis_geometry.sh  GPU   геометрия и проекции активаций
```

Шаги 4–8 имеет смысл запускать только после 1–2: они читают сохранённые векторы.

## Что дальше

Вторая модель; judge-based ASR вместо прокси по первому токену; более тонкий контраст для
read-части (на текущем случайное направление берёт AUROC 0.88, то есть задача слишком лёгкая);
и $\Delta$ между концептами в ортогональном дополнении к общей компоненте — раз она
концепт-независима, различия живут в остатке.
